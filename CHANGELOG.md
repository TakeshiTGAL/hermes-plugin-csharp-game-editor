# Changelog

## 0.6.0

- A read that runs at once is disk text only: `read_text` (`.unity`, `.prefab`, `.asset`, `.cs`), `asset_find`, `prefab_info`, and `describe`. `set_active_instance` only picks the editor. A read that asks the editor (hierarchy, console, component values, reflection, a test job) is a plan. `unity_docs` stays not read-only because it sends to docs.unity3d.com, and the call is a plan.
- `apply_plan` copies open scenes that have unsaved changes, and the bytes of the files the plan names (including `.meta`). After the steps, a changed file the plan did not name is put back, and a file this apply created that the plan did not name is put back. A .meta stays when the asset or folder was already on disk before the plan. Assets and folders under `Assets` that have no `.meta` when the plan is made are named, and the `.meta` Unity writes for them is an effect of the plan. A Unity `.meta` (it starts with `fileFormatVersion`) whose asset or folder is already missing is named, and a change Unity makes to it is an effect of the plan. A `.meta` that does not start that way is still put back. When `Packages/manifest.json` lists a package that `Packages/packages-lock.json` does not, the plan names the lock file and Unity's rewrite of it is an effect of the plan. A lock that already lists every manifest package is still put back if it changes. `Library`, `Temp`, `Logs`, `obj`, `.git`, and hidden directories are left out; `UserSettings` and the project root are included. The plan names a new folder's `.meta`, every file inside a folder it deletes, `Packages/manifest.json` and `Packages/packages-lock.json` for a package add or remove, and a `.csproj` or `.sln` a compile writes. Those are not put back. Writing the old bytes of a scene does not restore its unsaved flag, so a scene that was unsaved is marked unsaved again. Measured on Unity 6000.6.6f1: `SaveScene` with `saveAsCopy` true leaves the scene unsaved, and restoring bytes then `AssetDatabase.Refresh` leaves the in-memory object and clears the unsaved flag.
- "inside:" lines are a draft from MCP for Unity's C# (`tools/extract_side_effects.py`). They are not the success check. Success is a separate measurement: play mode and a frame count that advanced; a compile that started and finished, then no `error CS` in the console; a test job's per-test rows checked against its summary and its progress, with a start time and a finish time; a player build whose output path is on disk and whose bytes changed. Upstream's "Entered play mode." and a job status of succeeded are not that measurement. MCP for Unity 10.3.0 does not write a test result file. A failed test, 0 tests, or a job with no row per test is an error. A build that says succeeded and leaves no new output is an error.
- Making a plan does not send `execute_code`. The reply says the step was not sent. Component values are not in the fingerprint, because reading them runs C# in the editor. That read runs only inside `apply_plan` (`component_values`, and the editor value of an asset replace).
- Overwriting an existing asset lists every serialized field of the one MonoBehaviour document, including fields inside lists. If that document cannot be read, there is no plan. The editor value is read when `apply_plan` runs; a dirty value is named in the error and is not overwritten. A text edit names the characters the range removes, and a removal is in the second question. `create_script` with `overwrite` true shows the file's current text. A file that is not text YAML, has a byte-order mark, or is a nested or stripped prefab is refused and not given a note that lets it through.
- `run_tests` and a player build save open scenes with unsaved changes first (upstream `TestRunnerService.cs:569`, `BuildRunner.cs:265`); the plan names the scene and its sha256 on disk, and changes made before the plan get the second question. `run_tests` is refused when an open scene has no path, because Unity's test runner would open a save dialog. Attributes are read the way C# writes them, including several names in one pair of brackets. A script the parser cannot finish is treated as editor code. A script in an `Editor` folder, an assembly definition whose `includePlatforms` names Editor, and a script already on disk that Unity runs by itself, get the second question when the plan would compile or run them. A script that changed on disk after the last compile is included when the plan only compiles. A folder delete names every file inside it, or a count and the first names when that list would not fit the second question. Unity's window layouts under `UserSettings/Layouts` (`.dwlt`) stay as Unity wrote them. A file that was on disk when the plan was made is put back even if it was already gone when the steps started. A file such a reload writes that the plan did not name is put back. A .meta stays when the asset or folder was already on disk before the plan.
- The second question is the full summary. Code is not shortened. It is sent only when it fits Hermes 0.22.2's Telegram (escaped UTF-16), Slack, and Discord cards (`tests/test_gateway_render.py`). A summary that does not fit is not sent, and `confirm_risky_plan` asks instead. Line and paragraph separators, carriage returns, and bidi marks are shown escaped. Logs go to `<HERMES_HOME>/plugin-data/agent-plugin-csharp-game-editor-<hash>/logs`.
- `unity_docs` is not marked read-only (it sends to docs.unity3d.com), so Hermes asks. New ops: `create_asmdef` (a game, EditMode, or PlayMode assembly definition in one approval), `asset_find` and `prefab_info` (read from disk; no asset loads, no code runs), and `describe` on every tool (one op's arguments in full and what it does inside). `create_script` refuses anything but `.cs` when the plan is made. Deleting a folder that holds scripts waits for the compile. A file named by folder and name is checked for links where upstream joins them. More key and credential names are refused. Each tool definition is under 5 KB (71 KB in all, from 138 KB).
- Upstream's `manage_animation.get_parameter`, `manage_vfx.get_info`, and three ProBuilder reads load assets on their path, so they are planned steps now.

## 0.5.0

- After a step that changes scripts, the plugin asks Unity to refresh and compile (`refresh_unity` with a compile request) and waits for a compile that started after that step, with no early exit. A Unity editor in the background did not start the compile of an edited script on its own, so 0.4's "nothing started in 8 seconds" reported a false "no errors" and saved. `error CS` lines from that compile stop the plan.
- `batch_execute` is expanded into its commands, each checked and shown like a step of its own and run one at a time; a batch inside a batch is refused. `execute_code` replay is sent as the exact code from the history, which the plan shows. `execute_custom_tool` shows the custom tool's source file, or is refused.
- Only the newest plan can run, within 10 minutes. A plan that deletes, runs editor code, can lose unsaved work, or sends or writes outside the project shows its whole text in an MCP question inside `apply_plan`. Where Hermes cannot show that question (its terminal CLI fails MCP questions closed), `apply_plan` runs nothing and asks for the new `confirm_risky_plan`, which Hermes asks about once more. A short failure before anything runs keeps the plan.
- Path arguments are the ones MCP for Unity's code hands to a file system call, extracted from its source (`file_params` in `bridge/ops_table.json`); `memory_compare_snapshots` no longer reads files outside the project. The fingerprint includes every serialized component value, and a plan whose fingerprint cannot be read does not run.
- Player builds go to `<project>/Builds` and snapshots to `<project>/MemoryCaptures` (upstream's defaults); inside `Assets` they are refused. A text edit carries the script's current sha256. `create_script` with `overwrite` true replaces the whole file through a text edit guarded by its sha256 (refused when the file has text above its first `using` line, where upstream refuses edits). A plan follows the effect of its own earlier steps (a save after a scene it creates). A modify in play mode is marked as refused by Unity.
- Each `unity_*` schema lists every argument with MCP for Unity's own type and description, and upstream's notes on each tool. A refusal of the request names the accepted ops or arguments and is not an error, so wrong guesses do not trip Hermes' three-strike pause. A change op called on a `unity_*` tool returns its plan.
- New reads: `component_values` (serialized fields through SerializedObject; no project getter runs), `validate_script`, `manage_script_capabilities`, `unity_reflect`, `unity_docs` (sends the query to docs.unity3d.com), and `execute_code.get_history`.
- `apply_plan` waits for test and build jobs and returns their result, and sends MCP progress notifications when the client passes a progress token. After a PlayMode run it waits until the test runner has restored the open scenes, and a plan is not measured against the runner's temporary scene.
- Argument types are checked against MCP for Unity's schema before a plan is made. A step's file effect follows the upstream action, not the tool name (`manage_build.scenes` only uses the scenes it lists). While the editor reloads on entering play mode, the plugin waits for it instead of picking another editor.
- The README gives the MCP for Unity package's git URL pinned to 10.3.0 and the stdio setting. Replies are English only.

## 0.4.0

- A change is two calls. `plan_batch` changes nothing and returns the whole change in words: each step, every value (script text in full), each file it creates, replaces, or deletes, and what is lost. `apply_plan` runs that plan once. `unity_batch` and the elicitation question are gone.
- `apply_plan` is the only tool with `readOnlyHint` false, so Hermes asks once before it runs. The twenty `unity_*` tools run only the reads in `bridge/read_allowlist.json` and refuse every other op.
- A plan records the editor state it was made against (selected editor, project, play mode, open scenes and their objects, and the files it names). `apply_plan` runs nothing when that changed and names what changed.
- After script steps, `apply_plan` waits for Unity's compile and stops on `error CS` lines.
- With more than one editor open, `set_active_instance` picks one (it is a read: routing only). The plan names that editor and `apply_plan` sends to it.
- Ops that only looked like reads (`apply_text_edits.read`, `script_apply_edits.get_sha`, `script_apply_edits.read`) are merged into one op per upstream tool. Component reads (they call property getters) and `list_packages` (it asks the package registry) are no longer reads.
- `manage_scene.save` and `create` take a `.unity` path and split it into `name` and folder the way upstream expects. An untitled scene asks for a path.
- `File/Exit` and `Unity/Quit` are refused like `File/Quit`. Deleting `Assets`, `Packages`, or `ProjectSettings` as a whole is refused.

## 0.3.0

- Twenty tools (`unity_editor` through `unity_generate`, plus `unity_batch`) cover every upstream operation from mcpforunityserver 10.3.0. Pass `op` and `arguments`.
- A read runs immediately. A change, a delete, running code, or a send is shown once with the decoded values and runs only if you accept. A batch shows every step and asks once. Declining, a missing question, or a question that would be cut sends nothing.
- The tools are marked read-only so Hermes skips its name-only trust prompt. The bridge still asks with the content.
- Paths are decoded the same way Unity decodes them before the check. A form that would decode differently on a second pass is refused. `File/Quit` is refused. `File/Exit` is not on that list.
- `manage_scene.save` refuses a scene this process has not seen, and a scene file that changed on disk, unless `overwrite_disk_changes` is true.
- The upstream child has telemetry forced off and no `HOME` variable. The package still resolves the account home and, with telemetry off, still writes `customer_uuid.txt` under `Library/Application Support/UnityMCP` when that file is absent.
- The README states the transport cases this check saw: explicit EditorPrefs `0` is stdio, and a missing key is HTTP at `http://127.0.0.1:8080`.
- The README states the refusal and failure sentences this check saw: a decoded path, `File/Quit`, a denied question, and no running editor.

## 0.2.3

- On HTTP, the bridge activates every non-core MCP for Unity group at start and reads `tools/list` again, so tests, UI, docs and ProBuilder stay listed. A later tools-list change is read before the next call.
- `save_scene` refuses a scene this process has not seen, even with `overwrite_disk_changes`. Seen hashes are stored beside the log directory, or under plugin data, and are not written into the default Hermes home.
- Tool schemas keep the arguments each action uses. `edit_scene_batch` names every allowed step in the schema enum, including `probuilder_set_pivot`. A path under the temp directory is allowed when it stays there. A player build can use that directory.
- `delete_gameobject` does not send MCP for Unity's delete. A confirmed removal uses Undo. A prefab child must appear in `GetRemovedGameObjects`, and after `save_scene` its fileID must be in `m_RemovedGameObjects`. A failed pre-pass sends nothing else.
- Material and ScriptableObject writes, and `save_scene`, call `AssetDatabase.SaveAssets`. A PlayMode job whose summary was dropped by a domain reload can still pass when the persisted counts show every test finished and `failures_so_far` is empty.
- `read_script`, `search_script`, `read_console` and `shader_info` ask. `preview_csharp` does not ask and returns a one-time `preview_id`. `run_csharp_in_editor` execute runs only that same code. `execute_custom_tool` asks and checks every string. The bridge does not depend on the `mcp` package.

## 0.2.2

- Each VFX, animation, graphics, ProBuilder and AI operation is its own tool, so the approval names the operation. `preview_scene_batch` lists the steps and returns a one-time `plan_id`. `edit_scene_batch` runs only that plan and asks once. Without the plan, nothing is sent.
- A file name is refused only when it is an exact key file or a key extension (`.env`, `credentials.json`, `serviceAccount.json`, `*.pem`, `*.keystore`, `id_rsa`, and similar). `Token.cs`, `SecretDoor.prefab` and `my_api_key.txt` are not refused.
- `create_scripts` fails when `error CS` names a path just written. Calling it again replaces that file. `error CS` lines that name other files are a note, and the call succeeds.
- Prefab recording matches serialized property paths. `position`, `rotation` and `drag` match the scene fields. `save_scene` refuses only when nothing was recorded and the scene was not marked dirty. A missing or dead instance ID, a memory-only value, and a mix of recorded and missed properties do not block a later save.
- `delete_gameobject` succeeds when `GetRemovedGameObjects` confirms a prefab child, and fails when children were seen but not confirmed.
- `component_values` keeps `page_size`, `cursor` and `include_properties`. Built-in UI and VFX types are sent by their full names. A pending build is a job, not a finished player. PlayMode test assemblies also reference `UnityEditor.TestRunner`.

## 0.2.1

- Read Unity's EditorPrefs and do not write them. An explicit 0 uses stdio. Any other value, including a missing key, uses HTTP on this machine's loopback. An HTTP server that is already listening is used as it is.
- `delete_gameobject` sends MCP for Unity's delete. A prefab-instance child is recorded first. A property write records the instance ID from the reply. `not-recorded` and a missing ID fail the call, and `save_scene` does not write that scene. A memory-only value says so and still saves.
- `set_renderer_color` keeps MCP for Unity's `property_block` default. `create_unique` is sent only when asked. `create_scripts` fails when any `error CS` line remains. A batch may add built-in components and records those writes once.

## 0.2.0

- Reach every MCP for Unity 10.3.0 operation except the ones listed in the README, under tool names that say whether a call reads, changes, or deletes.
- Refuse symbolic links, hidden paths, key-like file names and silent overwrites. `save_scene` saves a scene that was already unsaved when first seen, and refuses only when the file changed on disk.
- `edit_scene_batch` does not run `add_component`, `editor_settings_edit` or `build_settings_edit`. PlayMode assemblies do not reference `UnityEditor.TestRunner`. `edit_script_structure` requires `precondition_sha256`. Renderer color defaults to `create_unique`. Deletes use `Undo.DestroyObjectImmediate` and component writes record prefab overrides. The tools stay listed when Unity Hub has no editor.
- `create_scripts` and `edit_scene_batch` put one piece of work behind one approval.
- `test_results` adds a note: passed is true only when at least one test ran and none failed.
